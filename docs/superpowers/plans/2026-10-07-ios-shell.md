# iOS shell: the whole GoHealthMe product inside the iPhone app

> Plan written 2026-10-07 02:10 JST from a four-lens research pass (auth, money, WebView shell, native pairing). Executed the same night. Andre's requirement: everything the web app does must work in the iPhone app, with Apple Watch pairing as one tap.

## Verdict

webview-shell. All four lenses converge: the web app already does every flow Andre wants (sign in, create/join/fund challenges, stake USDC, verdicts, payouts, name claim) as in-page code, and on the email-OTP path every one of those completes inside WKWebView with zero popups and zero app switches: Dynamic's Turnkey embedded wallet signs silently in-page (app/app/providers.tsx:205 transactionConfirmation required:false), the server accepts the Dynamic JWT so no signature prompts (app/lib/server/wallet-auth.ts:194-208), gas comes from the treasury drip (app/lib/server/gas-drip.ts), and settle/ENS/faucet are server-signed. A native rebuild would re-implement ~every screen (the Dynamic RN SDK is a rewrite, not a shell) for no user gain tonight. The shell is the existing Expo 54 app (mobile/) with react-native-webview 13.15.0 loading https://gohealthme-tokyo.vercel.app; Apple Watch pairing stays native inside it by intercepting the page's own gohealthme://pair?code= navigation and, with a small web change, by the page posting the code to the shell so pairing is one tap plus the system Health sheet. Two things cannot work in a WKWebView and are hidden in the shell with an honest one-line pointer to Safari: Sign in with Base (keys.coinbase.com popup plus WebAuthn for a relying party we cannot claim) and "I already have a wallet" (WalletConnect app-hop per action, relay resume unverified). Repo for all paths below: /Users/andrechuabio/Desktop/eth/gohealthme-tokyo-hotfix (main, 6e9083b).

## Sign-in inside the shell

Yes, via email OTP only. SignInOptions (app/components/SignInPanel.tsx:60-113) uses useConnectWithOtp (connectWithEmail / verifyOneTimePassword), never opens Dynamic's modal, signs through the Turnkey iframe, and Dynamic persists the session in localStorage, which react-native-webview keeps in WKWebsiteDataStore.defaultDataStore (incognito false, cacheEnabled default) across launches. Dynamic's SDK explicitly persists OTP state to survive webview remounts. Not possible in the shell: Sign in with Base (app/lib/useBaseAccountConnect.ts:106, popup to keys.coinbase.com with window.opener messaging plus a passkey ceremony for RP keys.coinbase.com, both refused by WKWebView) and the own-wallet WalletConnect path (Dynamic default mobileExperience 'in-app-browser' leaves the shell; 'redirect' costs an app switch per connect, session proof, approve and join, with relay resume unverified). Both get hidden when the UA carries GoHealthMeShell/, with one line telling existing Base or own-wallet accounts to use Safari. Unverified until device QA: the Turnkey iframe inside WKWebView and that the Dynamic dashboard does not force a passkey at embedded-wallet signup (forceAuthenticatorAtSignup); if it does, flip it off in the dashboard.

## Transactions inside the shell

Yes on the email path, with no new wallet code in the shell. createPool, approve, joinPool, fundPool, withdraw, claimRefund and sweep are client viem writeContract calls from getArcWalletClient (app/lib/wallet.ts:147-154) with silent embedded-wallet signing and treasury gas drip before the first write (app/lib/ensure-gas.ts, app/app/api/gas/drip/route.ts, authenticated by the Dynamic JWT so no prompt). Join is approve + joinPool (app/components/JoinPool.tsx:191-232), payout is pull-payment withdraw() asserted on the Withdrawn event (app/lib/useWithdraw.ts:139-171), create is useUsdcDeposit createPool then POST /api/challenges (app/components/CreateChallenge.tsx:438-482). settle, recordVerdict, ENS subname mint, faucet and the in-app balance withdrawal are server-signed (app/lib/server/agent/spotter.ts:457-486, app/app/api/ens/claim/route.ts). World ID (IDKit join proof and ID-for-Agents payout approval) needs the shell to hand https://world.org/verify to Linking.openURL and keep the page polling the bridge; the proof itself is no chain tx. Lost in the shell: the gasless paymaster path, which only exists for Base Account smart wallets (app/lib/useGasSponsorship.ts:91-101); email users were already on drip gas, so nothing they had is removed. Production answers HTTP 200 with no X-Frame-Options, CSP or COOP header, so the WebView loads it unobstructed.

## Hard limits and how they are handled

- Sign in with Base (Coinbase Smart Wallet passkey) cannot complete inside WKWebView: the keys.coinbase.com popup has no real window (react-native-webview's createWebViewWithConfiguration returns nil, onOpenWindow yields only a URL) and WebAuthn for RP keys.coinbase.com is refused without that domain's webcredentials association, which com.chuabiolabs.gohealthme cannot declare. Mitigation: hide it in the shell (task 7); Base accounts keep using Safari. Users worse off: anyone who created their account with Base or an external wallet cannot use the same address in the shell; they are told so in one line before they type anything.
- A new native build and TestFlight upload are required: react-native-webview is not in mobile/package.json (Expo SDK 54 pins 13.15.0). The local pipeline (mobile/scripts/apple-build.sh: prebuild --clean, pod install, archive, altool) handles it; the Founders internal group (Andre, Nikki) gets the build with no Beta App Review, the public Beta link waits on Beta App Review where a WebView-first binary raises guideline 4.2 (repackaged website); HealthKit read, background delivery and Keychain pairing are the native features to lead the review notes with.
- The web changes (shell detection, hidden Base/own-wallet options, one-tap pairing bridge, Junction via Safari sheet) must reach production before the shell can be QA'd: previews are behind Vercel SSO and the shell cannot open them. Andre promotes the deploy (CLAUDE.md rule); until then the shell against prod shows the old iPhone layout where 'Open the GoHealthMe app' still works via the gohealthme:// intercept but costs a second tap.
- Unverified until a real-device pass: Dynamic email OTP plus Turnkey iframe signing inside WKWebView, session persistence across kill and relaunch, and IDKit bridge polling resuming after the World App hop. If the Dynamic dashboard forces a passkey at embedded-wallet signup, in-shell email signup hits a WebAuthn prompt that fails; the fix is the dashboard toggle (forceAuthenticatorAtSignup off, security method OTP), which only a dashboard admin can flip.
- No universal links exist: mobile/app.json has no ios.associatedDomains, https://gohealthme-tokyo.vercel.app/.well-known/apple-app-site-association is 404, and the Associated Domains capability must be enabled on the App ID (Apple Developer admin). Not needed for the email path or Apple pairing (custom scheme covers it), but it is what blocks the own-wallet WalletConnect path and World App returning by https, so that path stays hidden in v1.
